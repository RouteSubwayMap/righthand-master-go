## 1. 引言

### 1.1 编写目的

本文档旨在详细描述"RightHand 左右手管家系统"的业务功能需求，明确系统应具备的功能范围和业务规则，为系统设计、开发、测试提供业务依据。

### 1.2 适用范围

本系统适用于个人及团队的日常工作与生活管理，包括任务管理、备忘录管理、联系人管理等核心功能模块。

### 1.3 术语定义

| 术语 | 定义 |
|------|------|

| 工作流 | 任务状态流转的规则和流程 |

## 2. 项目概述

### 2.1 项目背景

在现代快节奏的工作和生活中，人们需要高效地管理各类事务、任务和重要信息。RightHand 系统应运而生，旨在为用户提供一站式的个人与团队管理解决方案。

### 2.2 系统定位

RightHand 是一个集用户权限管理、备忘录管理、任务管理于一体的综合性管家系统，通过统一的产品选择入口，为用户提供便捷的事务管理服务。

### 2.3 核心价值

- **统一入口**：整合多个管理子系统，提供统一的产品选择界面
- **权限管控**：基于角色的细粒度权限控制，保障数据安全
- **灵活工作流**：可配置的任务状态流转机制，适应不同业务场景
- **数据隔离**：多用户数据完全隔离，保障隐私安全
- **可视化展示**：丰富的数据统计和可视化看板

### 2.4 目标用户

- 企业研发团队成员
- 项目管理人员
- 产品经理
- 需要个人事务管理的普通用户

### 2.5 系统功能概览

系统包含三大功能模块：

#### 2.5.1 用户权限管理
- 用户管理
- 角色管理
- 菜单管理
- 字典管理

#### 2.5.3 任务管理（统一事项管理）
- 统一仪表盘
- 事项列表（支持列表/日历视图切换）
- 联系人管理

## 3. 功能需求

### 3.1 用户认证与权限模块

#### 3.1.1 用户登录
- **功能描述**：支持用户名密码登录，登录后进入产品选择页面
- **输入**：用户名、密码
- **输出**：登录成功/失败提示，成功后显示可访问的产品列表
- **业务规则**：
  - 用户只能访问被授权的产品
  - 如果用户没有任何产品权限，显示提示信息
  - 支持退出登录功能

#### 3.1.2 用户管理
- **功能描述**：管理员可对系统用户进行管理
- **功能点**：
  - 查看用户列表（支持分页、搜索）
  - 新增用户
  - 编辑用户信息
  - 删除用户
  - 为用户分配角色
  - 启用/禁用用户
- **权限要求**：需要用户管理权限

#### 3.1.3 角色管理
- **功能描述**：管理系统角色及角色权限
- **功能点**：
  - 查看角色列表
  - 新增角色
  - 编辑角色
  - 删除角色
  - 为角色分配菜单权限
- **权限要求**：需要角色管理权限

#### 3.1.4 菜单管理
- **功能描述**：管理系统菜单结构
- **功能点**：
  - 查看菜单树形结构
  - 新增菜单（支持目录、菜单、按钮三种类型）
  - 编辑菜单
  - 删除菜单
  - 调整菜单排序
- **菜单类型说明**：
  - 目录：用于组织菜单的容器
  - 菜单：具体的功能页面
  - 按钮：页面内的操作按钮
- **权限要求**：需要菜单管理权限

#### 3.1.5 字典管理
- **功能描述**：管理系统数据字典，用于统一管理系统中的枚举值
- **功能点**：
  - 查看字典列表（按类型分组显示）
  - 新增字典项
  - 编辑字典项
  - 删除字典项
  - 启用/禁用字典项
- **内置字典类型**：
  - 备忘类型：工作、生活、学习
  - 优先级：高、中、低
  - 任务类型：普通任务、需求、Bug、生产事件
  - 状态：未完成、已完成
  - 性别：男、女
  - 需求类型：内部优化、行内需求
  - 需求状态：待澄清、待排期、开发中、测试中、待投产、已完成
  - 联系人群组：客户经理、研发、产品经理
- **权限要求**：需要字典管理权限

---

### 3.2 统一事项管理模块

#### 3.2.1 统一仪表盘
- **功能描述**：展示所有事项的统计数据
- **功能点**：
  - 显示待办事项数量
  - 显示进行中事项数量
  - 显示已逾期事项数量（红色警示）
  - 显示已完成事项数量
  - 按类型统计（任务/备忘/需求）
  - 按优先级统计
  - 显示完成进度
  - 展示近期活动趋势

#### 3.2.2 事项列表（支持视图切换）
- **功能描述**：统一管理所有事项，支持通过 Tab 切换不同视图
- **视图模式**：
  - **列表视图**：表格形式展示，支持排序、筛选、分页
  - **日历视图**：按日期展示，适合时间规划
- **功能点**：
  - 查看事项列表（支持多维度筛选、搜索、分页）
  - 新增事项（支持一次性任务和周期性任务）
  - 编辑事项
  - 删除事项
  - 标记事项为完成/未完成
  - 设置提醒
  - 更新完成进度（0-100%）
  - 管理标签
  - 设置分类
  - 设置优先级
- **事项信息包括**：
  - 标题、内容、类型（TASK/MEMO/REQUIREMENT）
  - 分类、优先级、标签
  - 开始时间、截止时间、完成时间
  - 状态（TODO/DOING/DONE/CANCELLED）
  - 进度、备注
- **周期性任务配置**：
  - 支持设置任务重复规则
  - 重复类型：每天、每周、每月、每年
  - 每周可指定具体星期几（如每周一、周三、周五）
  - 每月可指定具体日期（如每月1号、15号）
  - 可设置重复结束条件（永不结束、指定日期结束、重复指定次数后结束）
  - 系统根据重复规则自动生成后续任务实例

#### 3.2.3 联系人管理
- **功能描述**：管理个人联系人信息
- **功能点**：
  - 查看联系人列表（支持搜索、分组筛选）
  - 新增联系人
  - 编辑联系人
  - 删除联系人
  - 按分组查看联系人
- **联系人信息包括**：
  - 姓名、性别、手机号、邮箱
  - 分组、公司、职务
  - 备注、头像

#### 3.2.4 需求管理
- **功能描述**：管理个人或团队的需求，跟踪需求从提出到完成的全流程
- **功能点**：
  - 查看需求列表（支持多维度筛选、搜索、分页）
  - 新增需求
  - 编辑需求
  - 删除需求
  - 更新需求状态
  - 设置需求优先级
  - 关联相关事项或任务
  - 记录需求处理进度
- **需求信息包括**：
  - 需求标题、详细描述
  - 需求类型（功能需求/优化建议/Bug修复/其他）
  - 优先级（高/中/低）
  - 状态（待评审/已接受/进行中/已完成/已拒绝）
  - 提出人、负责人
  - 提出时间、预计完成时间、实际完成时间
  - 关联的事项ID列表
  - 备注说明
- **需求状态流转**：
  - **待评审(PENDING_REVIEW)**：新提出的需求，等待评审
  - **已接受(ACCEPTED)**：评审通过，准备实施
  - **进行中(IN_PROGRESS)**：正在处理中
  - **已完成(COMPLETED)**：需求已实现
  - **已拒绝(REJECTED)**：评审不通过或无法实现

## 4. 业务流程

### 4.1 用户登录流程

1. 用户输入用户名和密码
2. 系统验证用户身份
3. 验证成功后，加载用户可访问的产品列表
4. 用户选择要进入的产品
5. 根据用户权限显示对应的菜单和功能

### 4.2 事项创建与流转流程

1. 用户创建新事项，填写事项信息（标题、内容、类型、优先级等）
2. 事项初始状态为“待办(TODO)”
3. 负责人开始处理事项，将状态改为“进行中(DOING)”
4. 事项完成后，将状态改为“已完成(DONE)”
5. 系统记录事项状态变更日志
6. 相关人员收到事项状态变更通知

### 4.3 事项管理流程

#### 4.3.1 一次性事项流程
1. 用户创建事项，设置标题、内容、类型、优先级等
2. 可设置截止时间和提醒
3. 用户可随时更新事项进度
4. 完成后事项状态标记为“已完成”
5. 支持对事项进行分类和标签管理

#### 4.3.2 周期性事项流程
1. 用户创建周期性事项，选择重复类型（每天/每周/每月/每年）
2. 配置具体的重复规则（如每周的星期几、每月的几号等）
3. 设置重复结束条件（永不结束/指定日期/指定次数）
4. 系统根据规则自动生成后续的事项实例

### 4.4 需求管理流程

1. **需求提出**：用户创建新需求，填写需求标题、描述、类型、优先级等信息
2. **需求评审**：负责人或团队对需求进行评审
   - 评审通过：状态变为“已接受(ACCEPTED)”，分配负责人
   - 评审不通过：状态变为“已拒绝(REJECTED)”，说明原因
3. **需求实施**：负责人开始处理需求，状态变为“进行中(IN_PROGRESS)”
   - 可关联相关事项或任务
   - 记录处理进度
4. **需求完成**：需求实现后，状态变为“已完成(COMPLETED)”
   - 记录实际完成时间
   - 可选：关联验收标准
5. 每个生成的实例独立管理，可单独标记完成或编辑
6. 用户可以修改或删除周期性规则，影响后续生成的实例

#### 6.2.4 列表页面
- 表格形式展示数据
- 支持分页
- 支持搜索和筛选
- 支持新增、编辑、删除等操作按钮
- 操作列提供快捷操作

#### 6.2.5 表单页面
- 清晰的表单布局
- 必填项标识
- 表单验证提示
- 保存和取消按钮

#### 6.2.6 详情页面
- 完整展示对象信息
- 关联信息展示（如事项的评论、附件）

- 操作反馈及时明确
- 加载状态有提示
- 错误提示友好清晰
- 确认操作用对话框

## 7. 性能需求

### 7.1 响应时间

- 普通页面加载：< 2秒
- 列表查询：< 1秒
- 复杂查询：< 2秒
- 文件上传：< 5秒（取决于文件大小）

### 7.2 并发能力

- 支持多用户同时在线使用
- 系统应能稳定处理日常业务请求

### 7.3 数据容量

- 支持大量事项、联系人数据的存储和查询
- 列表分页展示，避免一次性加载过多数据

## 8. 安全需求

### 8.1 认证安全

- 用户必须登录后才能访问系统功能
- 密码加密存储，不可明文保存
- 会话超时自动退出

### 8.2 权限控制

- 基于角色的访问控制（RBAC）
- 用户只能访问被授权的功能
- 用户只能查看和操作自己的数据
- 管理员可以管理所有用户数据

### 8.3 数据安全

- 敏感数据加密传输
- 防止SQL注入攻击
- 防止跨站脚本攻击（XSS）
- 重要操作记录日志

### 8.4 数据隔离

- 不同用户的数据完全隔离
- 用户只能访问自己的事项、联系人等数据
- 管理员可以查看所有用户数据
