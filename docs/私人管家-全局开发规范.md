## 1. 技术栈约束

- **ORM**: GORM v1.25.12

### 1.3 数据库
- **MySQL**: 8.0+
- **字符集**: utf8mb4_unicode_ci

## 2. 架构约束

### 2.1 后端架构
- **单体服务架构**: 所有模块运行在一个进程中
- **分层结构**: Handler → Service → Model
- **统一入口**: `cmd/server/main.go`
- **模块化**: 按功能划分到 `services/` 目录

### 2.2 前端架构
- **单页应用 (SPA)**: 使用 Vue Router
- **组件化**: 复用组件放在 `components/`
- **组合式函数**: 业务逻辑封装在 `composables/`
- **状态管理**: Pinia stores 管理全局状态

### 2.3 数据模型
- **统一事项表**: `task_item` 支持 TASK/MEMO/REQUIREMENT 三种类型
- **简化状态**: TODO → DOING → DONE/CANCELLED (固定4状态)
- **软删除**: 使用 `deleted` 字段标记删除

### 18.14 UTF-8编码规范(重要)

#### 18.14.1 问题背景
PowerShell通过API创建中文数据时,可能因编码转换导致数据库存储乱码(`????`)。

**根本原因**:
- PowerShell的`ConvertTo-Json`默认使用UTF-16编码
- 通过管道传递给`Invoke-WebRequest`时可能发生编码转换错误
- 未明确指定HTTP请求的Content-Type charset参数

#### 18.14.2 PowerShell最佳实践
```powershell
# ✅ 正确做法: 明确指定UTF-8编码
$menuData = @{
    menuName = "需求管理"
    productCode = "task"
    menuType = 1
} | ConvertTo-Json -Depth 10

# 转换为UTF-8字节再转回字符串
$jsonBytes = [System.Text.Encoding]::UTF8.GetBytes($menuData)
$content = [System.Text.Encoding]::UTF8.GetString($jsonBytes)

Invoke-WebRequest -Uri $url `
    -Method POST `
    -Body $content `
    -ContentType "application/json; charset=utf-8" `
    -UseBasicParsing

# ❌ 错误做法: 可能导致乱码
$menuData = @{menuName="需求管理"} | ConvertTo-Json
Invoke-WebRequest -Uri $url -Method POST -Body $menuData -ContentType "application/json"
```

#### 18.14.3 Go后端规范
```go
// ✅ GORM自动处理UTF-8,无需特殊处理
menu := models.SysMenu{
    MenuName: "需求管理",  // Go字符串原生支持UTF-8
}
db.Create(&menu)

// ✅ Gin自动设置UTF-8响应头
c.JSON(http.StatusOK, gin.H{
    "code": 200,
    "data": menu,
})
```

**配置要求**:
- 数据库DSN必须包含: `charset=utf8mb4`
- 配置文件: `configs/config.yaml` 中 `database.charset: utf8mb4`

#### 18.14.4 前端Vue规范

#### 18.14.6 问题诊断流程

遇到中文乱码时的排查步骤:

**步骤1: 验证API返回**
```powershell
$menusResult = Invoke-WebRequest -Uri "http://localhost:9080/api/system/menus/11" `
    -Headers $headers -UseBasicParsing

$menuData = ($menusResult.Content | ConvertFrom-Json).data
$bytes = [System.Text.Encoding]::UTF8.GetBytes($menuData.menuName)

Write-Host "UTF-8字节: $(($bytes | ForEach-Object { '0x' + $_.ToString('X2') }) -join ' ')"
# 预期: 0xE9 0x9C 0x80 0xE6 0xB1 0x82 0xE7 0xAE 0xA1 0xE7 0x90 0x86
# "需求管理" = 4个字符 × 3字节 = 12字节
```

**步骤2: 检查数据库**
```sql
SELECT id, menu_name, HEX(menu_name) as hex_value 
FROM auth_sys_menu 
WHERE menu_name LIKE '%需求%';

-- 正确的HEX: E99C80E6B182E7AEA1E79086
-- 错误的HEX: 3F3F3F3F (问号)
```

**步骤3: 验证数据库字符集**
```sql
SHOW CREATE DATABASE righthand;
-- 应该看到: DEFAULT CHARACTER SET utf8mb4

SHOW CREATE TABLE auth_sys_menu;
-- 应该看到: DEFAULT CHARSET=utf8mb4
```

#### 18.14.7 快速修复指南

**场景1: API创建数据时乱码**
```powershell
# 1. 删除乱码数据
Invoke-WebRequest -Uri "http://localhost:9080/api/system/menus/{id}" `
    -Method DELETE -Headers $headers

# 2. 使用正确的UTF-8编码重新创建(见18.14.2)
```

**场景2: SQL初始化脚本乱码**
```bash
# ❌ 错误: 使用PowerShell管道
Get-Content init.sql | mysql -u root -p righthand

# ✅ 正确: 使用MySQL source命令
mysql -u root -p righthand < init.sql
```

**场景3: 数据库已有乱码数据**
```sql
-- 1. 备份数据
CREATE TABLE auth_sys_menu_backup AS SELECT * FROM auth_sys_menu;

-- 2. 清空表
TRUNCATE TABLE auth_sys_menu;

-- 3. 重新导入(确保SQL文件是UTF-8编码)
source /path/to/init.sql;

-- 4. 验证
SELECT id, menu_name, HEX(menu_name) FROM auth_sys_menu WHERE id IN (1,2,3);
```
