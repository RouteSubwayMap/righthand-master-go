## 1. 架构概述

### 1.1 设计目标

RightHand 系统采用前后端分离的单体架构，基于 Go + Vue 技术栈构建，旨在提供高性能、高可用、易维护的个人与团队事务管理平台。

**核心设计原则：**
- **模块化**：功能模块清晰划分，便于维护和扩展
- **高性能**：Go 语言的高并发特性保障系统性能
- **安全性**：完善的认证授权机制，数据加密传输
- **可扩展**：模块化设计支持功能扩展
- **易维护**：清晰的代码结构和完善的文档

### 1.2 架构特点

- **前后端分离**：前端 Vue 3 + 后端 Go，通过 RESTful API 通信
- **单体架构**：所有业务模块运行在单一进程中，简化部署和运维
- **数据隔离**：不同业务模块使用独立数据库 Schema
- **JWT 认证**：无状态认证，支持分布式会话

### 3.2 服务划分

系统采用前后端分离架构，划分为 2 个核心服务：

| 服务名称 | 技术栈 | 职责 | 端口 |
|---------|--------|------|------|
| 前端服务 | Vue 3 + Element Plus | 用户界面、交互逻辑、路由管理 | 5173 (开发) / 80 (生产) |
| 后端服务 | Go + Gin + GORM | 业务逻辑、数据访问、API 接口 | 9080 |

**后端服务内部模块划分：**

虽然后端是一个统一的服务，但内部按业务域划分为三个模块：

| 模块名称 | 职责范围 | 主要功能 |
|---------|---------|----------|
| auth 模块 | 用户认证与权限管理 | 用户登录、用户管理、角色管理、菜单管理、字典管理 |
| task 模块 | 统一事项管理业务 | 事项管理（列表/日历视图）、周期性任务、联系人管理、仪表盘统计 |

### 3.3 通信方式

- **前端 ↔ 后端**：RESTful API (HTTP/HTTPS)
- **后端模块间通信**：函数调用（同一进程内）
- **数据格式**：JSON

### 4.2 分层架构

后端服务采用经典的三层架构，所有业务模块共享相同架构：

```
┌─────────────────────────┐
│     Handler Layer       │  ← HTTP 请求处理、参数验证
├─────────────────────────┤
│     Service Layer       │  ← 业务逻辑处理
├─────────────────────────┤
│   Repository Layer      │  ← 数据访问、数据库操作
├─────────────────────────┤
│     Database            │  ← MySQL 数据库
└─────────────────────────┘
```

#### 4.2.1 Handler 层（表现层）
- 接收 HTTP 请求
- 参数解析和验证
- 调用 Service 层
- 返回 HTTP 响应

#### 4.2.2 Service 层（业务逻辑层）
- 实现核心业务逻辑
- 事务管理
- 调用 Repository 层
- 数据转换和处理

#### 4.2.3 Repository 层（数据访问层）
- 数据库 CRUD 操作
- SQL 查询封装
- 数据映射

- 联系人管理（CRUD）

## 8. 安全设计

### 8.1 认证机制

**JWT Token 流程：**
1. 用户登录，验证用户名密码
2. 生成 JWT Token（包含用户 ID、用户名、角色等信息）
3. 前端存储 Token
4. 后续请求在 Header 中携带 Token
5. 后端中间件验证 Token 有效性
6. Token 过期后重新登录

### 8.2 密码安全

- 使用 BCrypt 算法加密存储密码
- 密码强度要求：至少 8 位，包含大小写字母、数字
- 禁止明文传输密码（使用 HTTPS）

### 8.3 权限控制

**RBAC 模型实现：**
- 使用 **Casbin** 框架实现基于角色的访问控制
- 数据模型：用户 → 角色 → 权限（菜单/按钮）
- 前端根据用户权限动态渲染菜单和按钮
- 后端通过 Casbin 中间件进行接口级别的权限校验

**Casbin 配置：**
- **模型文件（model.conf）**：定义 RBAC 权限模型
- **策略存储**：使用 MySQL 数据库存储权限策略
- **适配器**：casbin-gorm-adapter，与 GORM 集成

**权限校验流程：**
1. 用户登录后，加载用户角色和权限到 Casbin Enforcer
2. 前端通过权限指令控制 UI 元素显示
3. 后端请求经过 Casbin 中间件，验证用户是否有权限访问该接口
4. 无权限请求返回 403 Forbidden

### 8.4 数据安全

- **SQL 注入防护**：使用 GORM 参数化查询
- **XSS 防护**：前端输入转义
- **CORS 配置**：限制跨域访问
- **HTTPS**：生产环境强制使用 HTTPS

## 9. 部署架构

### 9.1 部署方式

#### 方式一：直接部署

**后端部署：**
```bash
# 编译
cd righthand-go/cmd/server
go build -o righthand-server

# 运行
./righthand-server
```

**前端部署：**
```bash
# 编译
cd righthand-frontend
npm run build

# 部署到 Nginx
cp -r dist/* /usr/share/nginx/html/
```

#### 方式二：Docker 部署

**Dockerfile (后端)：**
```dockerfile
FROM golang:1.24.8-alpine AS builder
WORKDIR /app
COPY . .
RUN go build -o righthand-server cmd/server/main.go

FROM alpine:latest
WORKDIR /app
COPY --from=builder /app/righthand-server .
COPY configs configs
EXPOSE 9080
CMD ["./righthand-server"]
```

**Docker Compose：**

> **重要说明**：Docker 部署时不包含 MySQL 服务，直接使用本机已部署的 MySQL 数据库。
> - 确保本机 MySQL 服务已启动并正常运行
> - 确保后端服务可以通过网络访问本机的 MySQL（默认端口 3306）
> - 如需从 Docker 容器访问主机 MySQL，可使用 `host.docker.internal` 作为数据库主机地址

```yaml
version: '3.8'

services:
  backend:
    build: ./righthand-go
    ports:
      - "9080:9080"
    environment:
      # Windows/Mac 使用 host.docker.internal 访问主机 MySQL
      # Linux 可使用 host-gateway 或直接配置主机 IP
      - DB_HOST=host.docker.internal
      - DB_PORT=3306
      - DB_USER=root
      - DB_PASSWORD=your_password
      - DB_NAME=righthand
    extra_hosts:
      - "host.docker.internal:host-gateway"  # Linux 系统需要
  
  frontend:
    build: ./righthand-frontend
    ports:
      - "80:80"
    depends_on:
      - backend
```

- **网络配置**：Linux 系统需在 Docker Compose 中配置 `extra_hosts` 以支持访问主机
