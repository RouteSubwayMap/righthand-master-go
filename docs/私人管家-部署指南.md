## 四、单机非 Docker 部署（生产推荐）

### 4.1 概述

本方式将后端和前端直接部署在 Linux 宿主机上，使用 Nginx 作为前端服务器和反向代理，使用 systemd 管理后端进程。适合生产场景。

### 4.2 部署架构

```
┌──────────────────────────────────────────────┐
│               Linux 服务器                     │
│                                              │
│  ┌──────────────┐    ┌──────────────────────┐│
│  │   Nginx :80  │───>│  righthand-server    ││
│  │ (静态文件)    │    │  :9080 (systemd)     ││
│  └──────────────┘    └──────────┬───────────┘│
│                                 │            │
│                    ┌────────────▼───────────┐ │
│                    │   MySQL :3306          │ │
│                    └────────────────────────┘ │
└──────────────────────────────────────────────┘
```

### 4.3 部署目录结构

```
/opt/righthand/
├── bin/
│   └── righthand-server        # 后端可执行文件
├── web/                         # 前端静态文件
├── configs/
│   └── config.yaml             # 后端配置文件
└── logs/
    └── app-YYYY-MM-DD.log      # 应用日志（按日期切割，当日文件）
```

### 4.4 第一步：在 Windows 开发机上构建发布包

```powershell
# 执行构建脚本
.\scripts\build-release.ps1
```

构建流程：
1. 读取 `VERSION` 文件 + Git commit hash 作为版本标识
2. 交叉编译 Go 后端为 Linux amd64 静态二进制
3. `npm install && npm run build` 构建前端
4. 收集所有部署资源到 `dist/righthand-{日期}-v{版本}/`
5. 自动修复换行符（CRLF → LF）
6. 打包为 `tar.gz`

构建产物：
```
dist/righthand-20260724-v1.0.0.tar.gz
dist/righthand-20260724-v1.0.0/
├── bin/righthand-server        # 后端可执行文件
├── web/                        # 前端静态文件
├── configs/config.yaml         # 后端配置
├── sql/init-database.sql       # 数据库初始化脚本
├── nginx/righthand.conf        # Nginx 配置
├── systemd/righthand.service   # systemd 服务单元
├── install.sh                  # 一键安装脚本
├── righthand-start.sh          # 启动脚本
└── righthand-stop.sh           # 停止脚本
```

### 4.5 第二步：上传并解压到目标服务器

```bash
# 上传
scp righthand-20260724-v1.0.0.tar.gz user@server:/tmp/

# SSH 登录目标服务器
ssh user@server

# 解压
cd /tmp
tar xzf righthand-20260724-v1.0.0.tar.gz
cd righthand-20260724-v1.0.0

# 赋予执行权限（Windows 打包的文件可能丢失执行权限）
chmod +x *.sh bin/righthand-server
```

### 4.6 第三步：编辑配置

```bash
# 编辑后端配置（数据库连接、JWT密钥等）
vim configs/config.yaml
```

需要修改的关键配置项（已用 `# TODO:` 标记）：

| 配置项 | 说明 |
|--------|------|
| database.password | 数据库密码 |
| jwt.secret | JWT密钥（生产环境务必修改） |
| cors.allow_origins | 允许的前端域名 |

```bash
# 编辑安装脚本配置
vim install.sh
```

需要修改的配置项：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| AUTO_INIT_DB | false | 是否自动执行SQL初始化 |
| DB_HOST | 127.0.0.1 | 数据库主机 |
| DB_PORT | 3306 | 数据库端口 |
| DB_USER | root | 数据库用户 |
| DB_PASS | "" | 数据库密码 |
| DB_NAME | righthand | 数据库名称 |

### 4.7 第四步：执行安装

```bash
sudo ./install.sh
```

安装脚本自动执行：
1. 赋予执行权限（防止解压后权限丢失）
2. 停止原有 righthand 服务和残留进程（防止 "Text file busy" 错误）
3. 创建 `/opt/righthand/` 目录结构
4. 复制后端可执行文件、前端静态文件、配置文件
5. 根据 `AUTO_INIT_DB` 配置决定是否执行 SQL 初始化
6. 配置 Nginx（复制配置、测试、重载）
7. 注册并启动 systemd 服务
8. 输出访问信息和默认账号

### 4.8 服务管理

```bash
# systemd 命令
systemctl start righthand       # 启动服务
systemctl stop righthand        # 停止服务
systemctl restart righthand     # 重启服务
systemctl status righthand      # 查看状态

# 使用封装脚本
./righthand-start.sh            # 启动（含 Nginx）
./righthand-stop.sh             # 停止

# 查看日志
journalctl -u righthand -f      # 实时控制台日志（systemd journald）
tail -f /opt/righthand/logs/app-$(date +%F).log   # 当日日志文件（按日期切割）
```

### 4.9 服务访问

| 服务 | 地址 |
|------|------|
| 前端应用 | http://服务器IP |
| 后端API | http://服务器IP:9080 |
| 健康检查 | http://服务器IP:9080/health |

### 4.10 配置模板说明

部署包中的 `configs/config.yaml` 基于 `scripts/config.yaml.tpl` 模板生成，与开发环境的区别：

| 配置项 | 开发环境 | 部署模板（生产） |
|--------|---------|----------------|
| server.mode | debug | release |
| log.output | both | both（控制台进 journald + 按日文件） |
| log.file_path | ./logs/app.log | ./logs/app.log（实际写入 app-YYYY-MM-DD.log） |
| database.host | host.docker.internal | 127.0.0.1 |
| database.password | "" | ""（待填写） |

## 五、配置说明

### 5.1 后端配置文件

文件位置：`righthand-go/configs/config.yaml`（开发）/ `/opt/righthand/configs/config.yaml`（部署）

```yaml
server:
  port: 9080                    # 后端服务端口
  mode: debug                   # 运行模式: debug/release/test

database:
  host: 127.0.0.1              # 数据库主机
  port: 3306                    # 数据库端口
  username: root                # 数据库用户
  password: ""                  # 数据库密码
  dbname: righthand             # 数据库名称
  loc: Asia/Shanghai            # 时区

jwt:
  secret: your-secret-key       # JWT密钥（生产环境务必修改）
  expire: 7200                  # Token过期时间（秒）

cors:
  allow_origins:                # 允许的前端域名
    - http://localhost:5173
```

### 5.2 Nginx 配置

文件位置：`scripts/righthand.conf`

- 监听 80 端口，serve 前端静态文件
- `/api/` 路径反向代理到后端 `127.0.0.1:9080`
- 支持 Vue Router history 模式
- Gzip 压缩和静态资源缓存

## 六、问题排查

### 6.1 端口占用

```bash
lsof -i :9080
lsof -i :80
```

### 6.2 数据库连接失败

1. 检查 MySQL 服务是否启动：`systemctl status mysql`
2. 检查配置文件中的数据库用户名和密码
3. 确认数据库 `righthand` 已创建
4. 执行初始化脚本：`mysql -u root -p righthand < sql/init-database.sql`
5. 检查防火墙是否允许 3306 端口

### 6.3 前端跨域问题

- 检查 `config.yaml` 中 CORS 的 `allow_origins` 是否包含前端访问地址
- Nginx 的 `proxy_pass` 地址是否正确

### 6.4 systemd 服务问题

```bash
# 查看服务日志
journalctl -u righthand -n 50

# 检查服务文件
systemctl cat righthand

# 重新加载配置
systemctl daemon-reload
systemctl restart righthand
```

### 6.5 Nginx 配置不生效（API 返回 404）

**症状**：安装 Nginx 并复制 righthand.conf 后，浏览器访问正常但登录失败，直接 curl 后端 9080 端口正常，curl Nginx 80 端口的 `/api/` 路径返回 404。

**逐步排查命令**：

```bash
# 1. 确认 Nginx 是否已安装
systemctl status nginx
# 若 Unit not found → 未安装，执行 sudo apt install nginx -y

# 2. 确认配置文件是否存在且被 include
ls -la /etc/nginx/conf.d/
grep "conf.d" /etc/nginx/nginx.conf
# 应有: include /etc/nginx/conf.d/*.conf;

# 3. 确认只有一个 server 块监听 80 端口（避免冲突）
sudo nginx -T 2>/dev/null | grep -E "listen.*80"
# 正常应只有一行输出，多个则存在冲突

# 4. 查看 righthand.conf 是否被加载
sudo nginx -T 2>/dev/null | grep "righthand.conf"

# 5. 确认 /etc/nginx/sites-enabled/ 目录为空（避免默认站点抢请求）
ls /etc/nginx/sites-enabled/
# 如果有文件，执行 sudo rm -f /etc/nginx/sites-enabled/*

# 6. 测试 Nginx 配置语法
sudo nginx -t

# 7. 强制重载配置（比 restart 更可靠）
sudo nginx -s reload

# 8. 验证修复
curl -I http://localhost/
curl http://localhost/health
curl -X POST http://localhost/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}'
```

**常见原因总结**：

| 原因 | 解决方案 |
|------|---------|
| Nginx 未安装 | `sudo apt install nginx -y` |
| `install.sh` 未自动安装 Nginx | 手动安装后补执行 `cp nginx/righthand.conf /etc/nginx/conf.d/` |
| 配置文件已复制但未重载 | `sudo nginx -s reload`（非 restart） |
| 默认站点 `/etc/nginx/sites-enabled/default` 抢了 80 端口 | `sudo rm -f /etc/nginx/sites-enabled/default` |
| 配置文件换行符为 CRLF | `sed -i 's/\r$//' /etc/nginx/conf.d/righthand.conf` |

### 6.6 查看日志

后端日志默认 `output: both`：控制台输出由 systemd 记入 journald；同时按日期写入文件 `logs/app-YYYY-MM-DD.log`（跨日自动切换新文件）。

```bash
# 实时查看控制台日志（journald）
journalctl -u righthand -f

# 实时查看当日日志文件
tail -f /opt/righthand/logs/app-$(date +%F).log

# 查看历史某天
less /opt/righthand/logs/app-2026-09-23.log
```

若文件未生成：检查 `config.yaml` 的 `log.output` 是否为 `file` / `both`，以及 `/opt/righthand/logs` 目录存在且服务可写；服务启动日志中若出现「日志初始化失败」告警，说明已降级为纯控制台输出（此时只能通过 `journalctl` 查看）。
